# Site Diary — Plan 1: Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pnpm monorepo with a Hono API on Postgres (Drizzle, row-level-security tenant isolation proven by tests), a React 19 PWA showing the Field Ops sign-in screen with switchable themes, CI on every PR, and Railway deployment config.

**Architecture:** Three workspaces: `packages/shared` (Zod schemas, ID helper, capability and role constants), `apps/api` (Hono + Drizzle; migrations run as the DB owner role, requests run as a restricted `app_user` role inside a transaction that sets `app.company_id` with `SET LOCAL`), and `apps/web` (Vite + React 19 + TanStack Router + Tailwind v4 reading CSS-variable tokens). In production, `apps/web` is served by a small Node server that also proxies `/api/*` to the API service over Railway's private network, so browser cookies stay first-party.

**Tech Stack:** Node 22, pnpm 10, TypeScript 5 (strict), Hono 4, Drizzle ORM + drizzle-kit, `pg`, Zod 3, `uuid` (v7), React 19, Vite 6, TanStack Router, Tailwind CSS 4, `vite-plugin-pwa`, `@fontsource/barlow-condensed`, `@fontsource/ibm-plex-sans`, `@fontsource/jetbrains-mono`, `@fontsource/archivo`, Vitest 3, Testing Library, Playwright, ESLint 9 (flat config), Prettier 3, GitHub Actions, Railway. Use the latest stable release of each at install time; the lockfile pins them.

**Spec:** `docs/superpowers/specs/2026-10-13-site-diary-core-design.md` · Roadmap: `docs/superpowers/plans/2026-10-13-core-roadmap.md`

## Global Constraints

- TypeScript `strict: true` everywhere; no `any` without an inline `// eslint-disable-next-line` and a reason.
- Every tenant-owned table has `company_id uuid NOT NULL` and an RLS policy (spec §7.4). The API never connects to Postgres as a role that can bypass RLS.
- Every table has `id uuid` primary key (UUIDv7, generated by the app), `created_at timestamptz`, `updated_at timestamptz`, `version integer NOT NULL DEFAULT 1`, `created_by uuid NULL`, `updated_by uuid NULL` (spec §7.5, §9).
- No hard-coded colours or fonts in components: everything goes through CSS variables in `apps/web/src/theme/tokens.css` (spec §8.2).
- Default theme `field-ops`, default mode follows the device (`system`) (spec §8.2).
- Secrets only in environment variables; `.env*` files git-ignored, with `.env.example` committed.
- User-facing copy never shows UUIDs (spec §5).
- Commit messages: conventional style (`feat:`, `chore:`, `test:`, `ci:`).

## Review Focus

1. **Pooled connection reuse after a tenant request**: the next query on the same pooled connection must see *no* tenant (zero rows), not the previous company's data. Pinned in Task 4, test `tenant context does not leak across pooled connections`.
2. **Messy slug and project-code input** (uppercase, spaces, leading or trailing hyphens, non-ASCII, too long): must be normalised or rejected with a readable message, never stored raw. Pinned in Task 2, tests `normaliseSlug` and `projectCodeSchema`.
3. **Browser storage unavailable or holding a garbage theme value** (private mode, `localStorage` throws, old value `"blue"`): the app must still render with defaults. Pinned in Task 6, tests `falls back when storage throws` and `ignores unknown stored theme`.
4. **Missing or malformed env var at boot**: the API must exit immediately naming the variable, not fail later on the first request. Pinned in Task 3, test `loadConfig names the missing variable`.
5. **A write that targets another company while in tenant A's context** (a bug that passes B's `company_id`): Postgres must reject it. Pinned in Task 4, test `cannot insert a row for another company`.

### Task 2: Shared IDs, slugs, capabilities and system roles

| store_keeper | company.view, projects.view | attendance, indent, stock, inward, outward |

  - `runMigrations(ownerUrl: string): Promise<void>`: Drizzle migrator, then applies `rls.sql` (idempotent).
- `rls.sql` (the exact policy shape; repeat for each tenant table: projects, roles, role_capabilities, audit_log):

```sql
DO $$ BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'app_user') THEN
    CREATE ROLE app_user LOGIN NOSUPERUSER NOBYPASSRLS;
  END IF;
END $$;
-- migrate.ts then runs: ALTER ROLE app_user PASSWORD <APP_DB_PASSWORD>, built with pg's escapeLiteral (never string-concatenated raw)
GRANT SELECT, INSERT, UPDATE, DELETE ON projects, roles, role_capabilities, audit_log TO app_user;
GRANT SELECT ON companies TO app_user;
ALTER TABLE projects ENABLE ROW LEVEL SECURITY;
ALTER TABLE projects FORCE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS tenant_isolation ON projects;
CREATE POLICY tenant_isolation ON projects
  USING (company_id = nullif(current_setting('app.company_id', true), '')::uuid)
  WITH CHECK (company_id = nullif(current_setting('app.company_id', true), '')::uuid);
-- companies: app_user may read only its own company row
ALTER TABLE companies ENABLE ROW LEVEL SECURITY;
ALTER TABLE companies FORCE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS own_company ON companies;
CREATE POLICY own_company ON companies FOR SELECT
  USING (id = nullif(current_setting('app.company_id', true), '')::uuid);
-- the owner role (migrations, platform admin) is exempt
```

  `FORCE ROW LEVEL SECURITY` also applies to the table owner, so the **owner connection must be a role with `BYPASSRLS`**. Railway's default `postgres` user is a superuser, which qualifies; the local test DB uses its initdb superuser. `migrate.ts` reads `APP_DB_PASSWORD` from the env and substitutes it; add `APP_DB_PASSWORD` to `Config` and `.env.example`.
- `scripts/test-db.sh start|stop`: initdb in `./.pgdata` with `/usr/lib/postgresql/16/bin` (fall back to `pg_ctl` on PATH), port 54329, prints `MIGRATION_DATABASE_URL` and `DATABASE_URL` for `.env.test`. In CI the Postgres service container is used instead.
